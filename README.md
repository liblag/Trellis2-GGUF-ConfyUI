# TRELLIS.2: стартовые профили Colab T4 16 GB

Репозиторий содержит полный исходный код ноды: `nodes.py`, `__init__.py`, `model_manager.py`, пакет `trellis2_gguf/`, патчи и 14 workflow. Основа — Aero-Ex/ComfyUI-Trellis2-GGUF; авторство и MIT-лицензия сохранены, исходная ревизия записана в SOURCE.txt. Старые бинарные wheels не включены: notebook собирает CUDA-расширения для T4 из закреплённых исходников.

## Логи и прогресс всех Trellis-нод

Встроены в ноду; менять ComfyUI или JSON workflow не требуется. Для каждой реально исполняемой ноды записываются start/inputs/done/error, длительность и traceback. Картинки и значения GPU-тензоров не копируются в лог: сохраняются формы, типы и устройство. Сведения о входах/выходах краткие, а не полные дампы данных. Кэшированные ComfyUI-ноды повторно не исполняются и новых логов не создают.

Отдельно отмечаются загрузка/выгрузка моделей, conditioning, sampling, decode, блоки shape-декодера и построение поверхности. У сэмплеров показаны реальные завершённые шаги; существующий ProgressBar ComfyUI также обновляется. Подробный статус появляется в панели внизу справа через локальное web-расширение. Оно не добавляет сериализуемые поля и не меняет входы workflow.

Каждые 20 секунд долгого этапа выводятся его название, прошедшее время, RAM процесса и свободная системная RAM. Интервал задаётся `TRELLIS_LOG_INTERVAL`. Через 120 секунд без нового шага/этапа сохраняется Python-стек рабочего потока; это диагностический снимок, а не доказательство зависания. GPU-операции не синхронизируются ради логов: времена — wall time вызовов, CUDA-ошибка может быть асинхронной. Одна неделимая CUDA-операция не даёт достоверного процента и не становится прерываемой от наличия heartbeat. Если Python целиком удерживает GIL или процесс убит системой, heartbeat также может остановиться.

Текст идёт в консоль ComfyUI (`/content/comfy-t4.log` в новом notebook); структурированные события — в `ComfyUI/output/trellis_logs/*.jsonl`. При ошибке прикладывайте конец консольного лога и JSONL соответствующей ноды. Проверки без GPU: `python -m unittest discover -s tests -v`. Проверка живого интерфейса и полного T4 inference ещё требуется.

Саму ноду notebook скачивает из **liblag/Trellis2-GGUF-ConfyUI**, а ComfyUI, ComfyUI-GGUF, CUDA-библиотеки и веса моделей — из их собственных источников. При переходе со старой Aero-Ex-ноды её папка целиком переносится в `/content/t4-node-backups/`, чтобы сохранить локальные изменения и исключить загрузку двух копий ноды.

## Полный notebook для Colab

[Открыть Trellis2_T4_Colab.ipynb в Colab](https://colab.research.google.com/github/liblag/Trellis2-GGUF-ConfyUI/blob/main/Trellis2_T4_Colab.ipynb)

Две основные ячейки: **1. Установка** (один запуск со всеми этапами) и **2. Запуск / перезапуск ComfyUI** (без установки и повторной сборки). После остановки сервера выполняйте только вторую ячейку. После удаления всей среды Colab потребуется установка заново. Завершённые этапы и собранные wheels кэшируются в текущей среде.

Исходный notebook пользователя переработан: Python 3.12; Torch 2.9.1 / torchvision 0.24.1 / torchaudio 2.9.1 cu126 закреплены constraints; CUDA toolkit 12.6 устанавливается рядом с системным; flex_gemm, CuMesh, o_voxel и nvdiffrast собираются под архитектуру T4 7.5. Независимые загрузки Git идут параллельно, CUDA-сборки — последовательно с MAX_JOBS=1 из-за ограниченной RAM Colab. Сборка при первом запуске может занимать десятки минут.

До запуска проверяются настоящие GPU-операции flex_gemm (включая neighbor-map), CuMesh и nvdiffrast. Успешный import o_voxel не считается проверкой полного экспорта. ComfyUI-GGUF установлен явно; перед публикацией ссылки проверяется загрузка Trellis-нод и native GGUF support. Туннель использует HTTP/2; процесс сервера пишет логи в файлы и не удерживает ячейку. Отдельная ячейка останавливает только записанные процессы этого notebook.

Вывод установочных процессов явно передаётся в ячейку через stdout/stderr PIPE, а не наследование системных дескрипторов Colab. Полный вывод каждого этапа также сохраняется в `/content/colab-install-*.log`; вывод запуска — в `/content/colab-launch.log`. Если сборка падает, нужен конец этого лога с первой ошибкой компилятора, а не только финальный CalledProcessError.

Сборка wheels запускается с `--verbose --no-clean`: видны команды и сообщения компилятора, успешно собранные объектные файлы остаются для повторного запуска. До и после каждой сборки печатаются свободное место, доступная RAM и cgroup memory.events/current/max (если доступны). Рост `oom_kill` во время неудачной сборки указывает на завершение процесса из-за лимита памяти; сам `No available output` не доказывает OOM.

Для сборки CuMesh явно устанавливается `libeigen3-dev`; путь `/usr/include/eigen3` передаётся C++ и nvcc, даже если Eigen отсутствует во вложенных Git-submodules. В PATH сборки добавлен `/content/venv312/bin`, чтобы находился установленный ninja. Этап builds проверяет эти зависимости отдельно и может исправить уже созданную среду без повторения полной установки.

Notebook содержит встроенный пакет скриптов и профилей; для его запуска не нужен токен GitHub. Рядом в colab/ лежат читаемые исходники и закреплённые Git-ревизии. Установка не запускает оригинальный автоустановщик с неподходящими бинарными wheels. Необязательный nvdiffrec PBR-preview и сторонняя цепочка Qwen в базовую установку не включены. End-to-end генерация на реальном T4 ещё не подтверждена.

Описанная ниже Apply_T4.ipynb — прежний небольшой патч для уже установленного окружения. Для новой среды используйте полный notebook выше.

Все 14 оригинальных workflow сохранены в example_workflows/. Исправлены устаревшие сериализованные параметры и индексы входов, включая вложенные subgraphs. Базовый профиль: GGUF Q4_K_M, sdpa, cuda, low_vram=true, keep_models_loaded=false, генерация 512, 12 шагов, лимит 49152 токенов, текстура 1024, tiled encoder/decoder, Xatlas. MultiView сохраняет несколько ракурсов, MeshOnly не генерирует texture slat. LowPoly сохраняет меньшие целевые числа полигонов; остальные ограничены 300000. Имена High/Max Quality сохранены для узнаваемости цепочки, но разрешение намеренно снижено для T4.

## Применение

1. Не перезапускайте среду Colab. Остановите только процесс ComfyUI.
2. Откройте Apply_T4.ipynb в той же среде либо скопируйте из него установочную ячейку в текущий notebook.
3. Загрузите архив Trellis2-T4.zip через эту ячейку. Она распакует профили, установит зависимости rembg с сохранением Torch constraints и применит точечный патч.
4. Запустите ComfyUI заново. Импортируйте JSON из example_workflows. Выберите свои изображения вместо примеров автора.
5. Для начала используйте Only_Mesh_Simple.json. MeshRefiner и TextureMesh требуют собственного входного mesh.glb в /content/ComfyUI/input/; измените путь в Load Mesh при другом имени файла.

## Удаление фона

remove_background=true сохранён. Патч t4_background.py выполняет rembg/u2net в отдельном CPU-процессе с двумя потоками, логом и общим тайм-аутом 180 секунд. Отмена проверяется каждые 0,2 секунды; зависший дочерний процесс завершается. Готовая альфа сохраняется без повторного удаления фона. Размер входа ограничен 2048 до обработки. Первый запуск скачивает модель; при медленной сети тайм-аут может сработать и выдаст явную ошибку вместо бесконечного ожидания. Это ограничивает зависание, но не доказывает причину прежнего сбоя.

install_patch.py сохраняет nodes.py.before-t4-background. Для отката восстановите этот файл как nodes.py и перезапустите ComfyUI. Повторная установка патча безопасна. Обновление репозитория может потребовать повторного применения.

## Особые варианты и ограничения

- Using_Qwen_Rembg.json: настройки Trellis и открытые controls вложенных цепочек обновлены. Дополнительные ноды удаления фона и Qwen normal-map остаются оригинальными. Модель Qwen Q8 в этом примере тяжёлая и НЕ подтверждена как помещающаяся в T4. Для начального запуска выбирайте обычные Simple/Only_Mesh, где используется исправленный PreProcess. Патч rembg не распространяется на сторонние Qwen/background nodes.
- MultiView: загрузите предусмотренные ракурсы. Лимит памяти всё ещё зависит от сложности объекта и числа видов.
- Full remeshing, заполнение отверстий и другие фазы оставлены на месте, чтобы сохранить назначение каждого варианта. Если отдельный этап не проходит, проверяйте его лог.
- Требуется установленный city96/ComfyUI-GGUF для загрузки Q4. Torch/CUDA не обновляются этим пакетом.
- Исходный commit указан в SOURCE.txt. Проверены схемы параметров, связи графа и управление worker с тестовой заменой rembg. Реальные GGUF/CUDA inference, качество удаления фона и полный GLB-экспорт на T4 локально не проверены. Это стартовые профили, а не гарантия запуска всех сложных цепочек в 16 GB.
